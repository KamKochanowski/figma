## 1. Which Claude platform capabilities matter for a website, per official sources (models and prices, limits, structured outputs, tools, caching, refusals and fallbacks, MCP, Agent SDK, Artifacts, what is new in 2026)?

### Takeaway
On 2026-10-29 the official lineup is Fable 5.1 ($10 in / $50 out per million tokens), Opus 5.5 ($4/$20), Sonnet 5.5 ($2/$10) and Haiku 5.5 ($0.10/$0.50 up to 100K-token prompts), all with 1M context, adaptive thinking, structured outputs, streaming, caching and citations. For a portfolio the real levers are model tier (a 40x list-price spread between Haiku 5.5 and Opus 5.5), prompt caching, a dedicated workspace with a spend limit, refusal handling, and the 2026 privacy and disclosure rules; Claude Artifacts cannot give anonymous visitors AI features (viewers need their own Claude account), so visitor-facing AI must run on your own API key.

- Anthropic positioning: start with Opus 5.5 for most workloads; Fable 5.1 for demanding reasoning and long-horizon agentic work; Sonnet 5.5 "the best combination of speed and intelligence"; Haiku 5.5 "for high-volume, latency-sensitive tasks such as classification, extraction, and routing". Comparative latency: Haiku fastest, Sonnet fast, Opus moderate, Fable slower. — [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview)

Haiku 5.5 up to 100K-token prompts $0.10/$0.50, write $0.125 / $0.20, read $0.01; Haiku 5.5 above 100K tokens $0.50/$2.50, write $0.625 / $1, read $0.05. Fable 5.1 $10/$50, write $12.50 / $20, read $0.25. Multipliers: 5-min write 1.25x, 1-h write 2x, read 0.1x (0.05x on Opus 5.5 and Sonnet 5.5, 0.025x on Fable 5.1). - Minimum cacheable prompt is 512 tokens on Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5; automatic caching (one top-level `cache_control`) launched Feb 19 2026. — [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)

#### Rate limits, spend caps, workspaces
- Start tier, per model class (Opus 5.5, Sonnet 5.5, Haiku 5.5 each): 1,000 requests/min, 2,000,000 input tokens/min, 400,000 output tokens/min; Build 5,000 / 5M / 1M; Scale 10,000 / 10M / 2M; Fable 5.x is lower (Start 1,000 / 500K / 100K). Only uncached input tokens count toward the input limit; cache reads do not. New organizations may start in a lower "Evaluation" tier. — [Rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- Monthly spend caps: Start $500, Build $1,000, Scale $200,000. You can set your own lower limit in Console and per-workspace spend and rate limits, but "You can't set spend limits on the default Workspace". At the tier cap the API returns HTTP 429 `enforced_spend_limit_reached` with no `retry-after` until 00:00 UTC on the 1st; at your own limit it returns HTTP 400. — [Rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- User profiles (launched Oct 20 2026): send `anthropic-user-profile-id` so a safety enforcement action can apply to one end customer instead of the whole organization; profiles are not billable and hold no conversation content; Anthropic advises keeping end-customer traffic in a separate organization from your own internal usage. — [User profiles](https://platform.claude.com/docs/en/manage-claude/user-profiles), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)

#### Messages API features relevant to a site
- Streaming uses server-sent events (`message_start` ... `message_stop`); structured outputs work with streaming. — [Streaming](https://platform.claude.com/docs/en/build-with-claude/streaming), [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- Structured outputs are GA (Jan 29 2026) on all current models: JSON Schema in `output_config.format`; supports string `enum`; does not support `minLength`/`maxLength`, numeric constraints or recursive schemas; objects need `additionalProperties:false`; incompatible with citations (HTTP 400) and with prefill. — [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- Forced `tool_choice` (`any`, `tool`) returns 400 on Opus 5.5, Sonnet 5.5 and Fable 5.1; Anthropic says to use `auto` with strict tool use (`strict:true`). — [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- Citations: set `citations:{enabled:true}` on document blocks; "`cited_text` does not count toward your output tokens"; citations "are guaranteed to contain valid pointers to the provided documents". — [Citations](https://platform.claude.com/docs/en/build-with-claude/citations)
- Web search tool versions `web_search_20250305`, `web_search_20260209` (dynamic filtering) and `web_search_20260318`; settings `max_uses`, `allowed_domains` or `blocked_domains`, `user_location`; results come with citations. — [Web search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)
- Web fetch: "Claude cannot fetch URLs that appear only in its own output"; it can fetch URLs from user messages, client tool results and earlier search/fetch results. Anthropic warns of residual data-exfiltration risk when untrusted content sits next to sensitive data and suggests `max_uses`, `allowed_domains`, `max_content_tokens`, or disabling the tool; since Oct 20 2026 organization admins can turn web fetch off or set domain lists on the Console Capabilities page. — [Web fetch tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- Files API is GA since Aug 19 2026 (no beta header): 500 MB per file, 1 TB per organization; files are scoped to the workspace (any key in the workspace can reference them; "never accept file IDs from untrusted sources"); not eligible for zero data retention. — [Files API](https://platform.claude.com/docs/en/build-with-claude/files), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- All current models accept text and image input; the media limit is 600 images or PDF pages per request with the 1M window (Mar 13 2026). — [Models overview](https://platform.claude.com/docs/en/about-claude/models/overview), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- API version `2026-10-21` and new SDKs shipped Oct 21 2026 (TypeScript SDK 1.0.0, Python 2.0.0; SDKs now Apache-2.0). In the new version `temperature`, `top_p`, `top_k` return 400 even at default values; `document` blocks in assistant messages and `citations` on user-message text blocks return 400. Latest `@anthropic-ai/sdk` on npm is 1.3.0 (Apache-2.0). — [Migration guide](https://platform.claude.com/docs/en/api/migration-2026-10-21), [Release notes](https://platform.claude.com/docs/en/release-notes/overview), [npm registry](https://registry.npmjs.org/@anthropic-ai/sdk/latest)

#### Refusals and server-side fallback
- Classifier refusals are HTTP 200 with `stop_reason:"refusal"` and `stop_details.category` (`cyber`, `bio`, `frontier_llm`, `reasoning_extraction`, `general_harms`, or null). A refusal can arrive mid-stream; partial output must be discarded. — [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)
- Server-side fallback (beta header `server-side-fallback-2026-07-01`, `fallbacks:"default"`) retries a declined request on the model Anthropic recommends for the category, in one API call, on the Claude API and Claude Models on Google Cloud (Anthropic managed). Not supported on the Batches API. "Claude Haiku 5.5 has no server-side fallback: with `fallbacks: "default"`, a declined request stays declined, and a list of fallback models returns a 400 error." — [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)
- Billing: since Sep 24 2026 refusals before any output are billed when the category is `bio`, `frontier_llm` or `reasoning_extraction`; mid-stream refusals are billed; fallback credit offsets the cache miss on the fallback request (not available after a Haiku 5.5 refusal). — [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback), [Release notes](https://platform.claude.com/docs/en/release-notes/overview)
- Asking the model to write its reasoning into the output text or into a `reasoning`/`thinking` JSON field can trigger a `reasoning_extraction` refusal; Anthropic says to ask for a short explanation or use summarized thinking instead. — [Refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)

### Inferences
- A grounded portfolio Q&A (about 5K tokens of facts, 2-4 sentence answers) is an easy task, so Haiku 5.5 (default) or Sonnet 5.5 (if Polish/English quality or tone needs it) is the cost-sensible tier; Opus 5.5 is Anthropic's general default but lists at 40x Haiku's price and probably gives no visible quality gain on this workload (untested; cost numbers in section 2).
- Because Opus 5.5 thinking cannot be disabled, even `effort:"low"` can add billed thinking tokens; Haiku 5.5 and Sonnet 5.5 give more predictable cost. Haiku 5.5 also has no server-side fallback, so a refused request needs your own graceful answer (the draft Worker already has one).
- Artifacts are a good place to prototype and to publish static, non-AI explainers (embed with allowed domains), not a way to give visitors Claude-powered features: those require the visitor's own Claude account.
- Anthropic's EU/GDPR story today is contractual (DPA with SCCs, no training, 30-day deletion), not geographic: there is no EU inference or workspace geo on the first-party API.
- Draft Worker status against these facts. Already done: structured output with schema, `effort:"low"`, server-side fallback beta with `"default"`, 1-h cache breakpoint on the system prompt, per-IP rate limit (8/min), question capped at 500 characters, history capped at 6 turns of 1,200 characters, `project_ids` whitelisted against `wiedza.json`, graceful fallback answer with email on refusal/max_tokens/429/502, no prices, injected instructions treated as content, SDK `^1.1.0` (current latest 1.3.0). Not done: server-side origin enforcement (CORS headers are set but a request from another origin is not rejected), Turnstile, streaming, server-held conversation history (the client can forge `assistant` turns today), schema `enum` for IDs, workspace spend limit, AI-disclosure text and privacy notice in the UI, logging policy, evals, `wiedza.json` calendar link still a placeholder (`UZUPELNIJ_LINK_CAL_COM`).

## 2. Integration patterns for a portfolio: chat grounded in case studies, "tailor to this brief", AI-guided tour, booking via Cal.com, voice, generative UI, AI-agent readability (how built on Cloudflare/Vercel, cost per conversation from official prices, abuse protection, GDPR, disclosure)

### Takeaway
Every pattern except voice is cheap on Haiku 5.5 or Sonnet 5.5 (computed: about $0.002 on Haiku to $0.036 on Sonnet per five-turn conversation, and $0.0002 to $0.03 per single-call feature; Opus 5.5 is about $0.07 per conversation), so the real work is abuse protection (Turnstile, per-workspace spend limit, server-side origin and history control), disclosure (EU AI Act Article 50 and Anthropic's Usage Policy both require telling visitors they talk to AI) and keeping chat as an addition to a fast, plain work list. Agent readability (llms.txt, markdown pages, JSON Resume, JSON-LD, an authless MCP server, optional WebMCP) is nearly free on Astro + Cloudflare and has working 2026 reference sites.

#### Cross-cutting: abuse protection
- Anthropic's own guidance: pre-screen input with a lightweight model such as Haiku 5.5 using a structured-output classifier (treat `stop_reason:"refusal"` as a harmful verdict); filter known injection patterns; harden the system prompt; throttle or ban repeat offenders; for indirect injection put untrusted content only in `tool_result` blocks, tell Claude what it is, state in the system prompt that tool/document content is untrusted data, and JSON-encode it. — [Mitigate jailbreaks and prompt injections](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks)
- OWASP LLM01 (prompt injection) mitigations: constrain model behavior, define and validate output formats, filter input and output, least-privilege (handle privileged functions in code, not in the model), human approval for high-risk actions, segregate external content; it states there may be no fool-proof prevention. — [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- Spend control facts: see section 1 (workspace spend limits, default workspace cannot have one, tier caps, 429 `enforced_spend_limit_reached` pauses all API use until the 1st; user profiles; separate org for public traffic).

### Inferences
Chat grounded in case studies
- Build: keep the draft Worker's approach (facts in the cached system prompt, no RAG: 10.7K characters of facts is far below Haiku 5.5's 100K-token price break). Add streaming (structured outputs support it; or stream plain text and send cards in a final event), change `project_ids` items to a schema `enum` of the 20 IDs, hold history server-side or sign it, enforce the origin server-side, add Turnstile, drop the cache TTL to 5 minutes unless traffic is steady, and test Haiku 5.5 vs Sonnet 5.5 on 30 real recruiter questions in PL and EN before choosing.
- Option worth knowing: put each case study in as a `document` block with `citations` on; the API then returns which document each sentence came from, and the site can show project cards from `document_title` with no JSON schema (citations and `output_config.format` cannot be combined in one request).
- Cost: $0.002 to $0.071 per five-turn chat (Haiku to Opus, cold); $1.9 to $71 per 1,000 chats.
- Abuse: Turnstile token on the first message and every N messages, rate limit per IP and per session, hard cap on turns (for example 8), max_tokens about 600, dedicated Console workspace with a monthly spend limit (for example $10-20) and a kill switch (env flag), Haiku pre-screen only if abuse appears (a classification call of about 100 tokens in and 20 out costs well under $0.0001 at Haiku 5.5 prices).
- Privacy: do not log content by default; if logging for quality, log truncated text without IP for 30 days and say so; no accounts, no cookies needed.
- Disclosure: a visible "AI assistant, answers only from Kamil's published work, may be wrong" line at the start of every session and in the input area; speak as "the assistant", not as Kamil in first person (the draft prompt already does).

Tailor to this brief
- Build: one non-streaming call with a schema {matched_project_ids (enum), why (per project), one_page_summary, gaps}; visitor pastes text (cap about 6,000 characters); optional URL via the web fetch tool with `max_uses:1` and a small `max_content_tokens`; optional PDF upload only if you accept prompt-injection risk (treat brief text as untrusted data: JSON-encode it and tell the model so). Render the one-pager as an Astro/React print view and let the visitor print or save as PDF (free, no server); Cloudflare Browser Run `/pdf` is the server-side alternative (free 10 min/day).
- Cost: $0.001 (Haiku) to $0.03 (Sonnet) to $0.06 (Opus) per run; negligible next to chat.
- Abuse and privacy: the brief is third-party text and may contain personal data (a job ad usually does not, a client brief may be confidential); say "do not paste confidential material", do not store it, no logging of the brief body.
- Disclosure: label the output "AI-generated selection and summary, review before sharing"; keep the original case-study links one click away.
- Novelty: no documented portfolio does this, so it is a differentiator but also unproven; keep it a secondary tab.

AI-guided tour
- Build: tours are tool calls that drive the UI: the model returns an ordered list of steps (enum of project IDs and section anchors, plus one-line narration from your own copy), the React island scrolls and highlights; no forced `tool_choice` on 5.5 models, so use a structured-output schema instead. Pre-write the narration so Claude only selects and orders (cheaper, safer). WebMCP and A2UI are alternatives, not requirements.
- Cost: about $0.0002 to $0.016 per route (Haiku to Sonnet).
- Abuse: closed schema means nothing free-form is rendered; still sanitize any model text.
- Disclosure: same AI line; make the tour skippable (santifer.io shows a "Skip intro" pattern on its typewriter intro).

Booking via Cal.com
- Build: the chat returns a `book` intent and the UI opens the Cal.com embed or link (no booking by the model); optionally the Worker reads availability from Cal.com API v2 with a server-side key. Fill the `kalendarz` placeholder in `wiedza.json`.
- Cost: Cal.com Free plan; LLM cost negligible. Abuse: use Cal.com's own event-type controls (minimum notice, booking limits; not verified here) and Turnstile on any custom form. Privacy: booking data goes to Cal.com (its hosting region, cookies and DPA were not checked).
- Disclosure: the model never confirms a booking itself.

Voice
- Build: browser mic -> STT -> your Worker -> Claude Haiku 5.5 -> TTS -> audio. Anthropic offers no audio endpoints, so STT/TTS come from Workers AI (Whisper/Nova-3, MeloTTS/Aura) or another vendor.
- Cost: about $0.003 to $0.055 per five-turn voice chat (computed, Workers AI speech prices), roughly 1.5x to 30x the Haiku text-only cost; about $0.25 per session is reported for OpenAI Realtime (about 130x).
- Abuse: voice raises both cost and abuse surface; gate behind Turnstile and a per-session minute cap.
- Privacy and disclosure: a visitor's voice is personal data under GDPR (inference); require an explicit click, show a recording indicator, say the reply voice is synthetic (AI Act Article 50 and the Usage Policy both apply). Recommendation: defer voice; it is the least aligned with a "55-second recruiter" use case.

Generative UI
- Build: Vercel AI SDK pattern (tool result -> React component) or A2UI-style declarative JSON rendered from a catalog of your own components (case-study card, before/after slider, spec sheet). Use a closed catalog so the model can never emit arbitrary markup.
- Cost: about $0.001 (Haiku) to $0.03 (Sonnet) per generated card.
- Disclosure: label generated layouts; keep a static fallback. MCP Apps is the route to put the same cards inside Claude/ChatGPT via your MCP server.

Agent readability
- Build on Astro (static output, nearly $0): (1) `/llms.txt` and `.md` siblings of case studies via `astro-slop` or `astro-llms-md`; (2) `/api/resume.json` (JSON Resume) and JSON-LD `Person`/`CreativeWork` in every page (Google says no special markup is needed for AI features, so this is for other agents); (3) authless remote MCP server on a Worker with `createMcpHandler` and 3-4 read-only tools (`list_projects`, `get_project`, `get_cv`, `book_intro` returning a Cal.com link), which a recruiter can add in Claude as a custom connector with "No sign in"; (4) enable Cloudflare Markdown for Agents; (5) WebMCP only as an experiment (origin trial, no score impact in Lighthouse); (6) NLWeb only if you want its `ask` protocol; `ask-endpoint` (section 4) is a lightweight NLWeb-compatible example.
- Cost: Worker Free plan; no LLM cost because the MCP server returns your data and the visitor's own client pays for its model.
- Abuse: read-only tools, rate limit, no secrets; return only public data.
- Privacy: no personal data processed beyond request logs; list the endpoint in `robots.txt` and the footer so humans can see it.
- Measured value: llms.txt has no effect on Google Search (Google's own statement) but is audited by Lighthouse and used by agents and developer tools; treat it as low-cost hygiene, not SEO.

What to build first (ordering by value for a 55-second recruiter and effort)
1. Fix and ship the chat (Haiku 5.5 or Sonnet 5.5, Turnstile, disclosure, spend limit); 2. "Tailor to this brief" as a second tab; 3. llms.txt, `.md` pages, JSON Resume, MCP server (cheap and visible to the AI-specialist audience); 4. tour; 5. booking intent; 6. generative UI; 7. voice last or never.
